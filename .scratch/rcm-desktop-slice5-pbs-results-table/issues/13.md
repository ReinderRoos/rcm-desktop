## What to build

Lever de pure adapterlaag voor de PBS-resultatentabel op, zonder Qt-UI.
Deze slice verrijkt het run-contract met geaggregeerde PBS-rij-data zodat
de volgende slice de tabel direct kan renderen.

End-to-end gedrag van deze slice (zonder view-aanpassingen):

- Uitbreiding van bestaande module `rcm_desktop.adapter.result_view_service`
  met:
  - `PBSResultRow` dataclass (12 velden, vast).
  - `build_pbs_rows(project, pbs_results) -> list[PBSResultRow]` —
    deterministische DFS-aggregatie langs `PBSItem.parent_pbs_id`.
- Additieve uitbreiding van `RunResult` met
  `pbs_rows: list[PBSResultRow]` (default `[]`).
- `run_service.run(...)` vult op happy path zowel `metrics`/`rows` als
  `pbs_rows` in één aanroep; bij foutpaden
  (`RUN_PRECONDITION_NOT_MET`, `RUN_INTERNAL_ERROR`) blijft
  `pbs_rows == []`.
- `build_pbs_rows`-eigenschappen:
  - DFS-volgorde root → kinderen → kleinkinderen.
  - **Stable child-sort binnen één parent**: alfabetisch op `pbs_id`
    (geen afhankelijkheid op dict-iteratie-volgorde).
  - Per knoop: `*_self` uit `pbs_results.get(pbs_id)` (PBS zonder
    result ⇒ `*_self == 0.0`).
  - Per knoop: `*_total = *_self + Σ children.*_total` voor de drie
    optelbare velden (faalmomenten, downtime, kosten).
  - `unavailability_pct_total` herberekend uit
    `total_downtime_hr_total / (config.lifecycle_years × 8760) × 100`.
  - `bouwdeel_naam` altijd uit `PBSItem.bouwdeel_naam` (single source
    of truth, ook wanneer `PBSResult.bouwdeel_naam` aanwezig is).
  - **Defensieve handling**: missing-parent ⇒ knoop als root,
    `level == 0`; cycle ⇒ via `visited`-set, knoop als root, geen
    exception.
  - `level` (0 = root) en `sort_path` (tuple van pbs_id's van root
    tot self) correct gevuld.

`PBSResultRow`-veldset (vast, voor implementatie):

```
fm_id-equivalent veldenset:
- pbs_id: str
- bouwdeel_naam: str
- parent_pbs_id: str | None
- level: int
- sort_path: tuple[str, ...]
- expected_failures_self: float
- total_downtime_hr_self: float
- total_cost_eur_self: float
- expected_failures_total: float
- total_downtime_hr_total: float
- total_cost_eur_total: float
- unavailability_pct_total: float
```

## Acceptance criteria

- [ ] `rcm_desktop.adapter.result_view_service` levert nu ook
      `PBSResultRow` en `build_pbs_rows(project, pbs_results)`; geen
      Qt-imports.
- [ ] `PBSResultRow` bevat exact: `pbs_id`, `bouwdeel_naam`,
      `parent_pbs_id`, `level`, `sort_path`,
      `expected_failures_self/_total`, `total_downtime_hr_self/_total`,
      `total_cost_eur_self/_total`, `unavailability_pct_total`.
- [ ] `build_pbs_rows` retourneert DFS-volgorde root → kinderen →
      kleinkinderen.
- [ ] `build_pbs_rows` sorteert children binnen één parent
      alfabetisch op `pbs_id` (deterministisch, los van
      dict-iteratie-volgorde).
- [ ] `build_pbs_rows` aggregeert self + alle descendants voor de drie
      optelbare velden (faalmomenten, downtime, kosten).
- [ ] `build_pbs_rows` herberekent `unavailability_pct_total =
      total_downtime_hr_total / (config.lifecycle_years × 8760) × 100`.
- [ ] Parity-test: voor een single-leaf-PBS zonder kinderen is
      `unavailability_pct_total` identiek aan
      `pbs_results[pbs_id].unavailability_pct`.
- [ ] PBS zonder eigen `PBSResult` (parent-only / structurele knoop)
      krijgt `*_self == 0.0`; aggregatie blijft correct.
- [ ] Onbekende `parent_pbs_id` (wijst nergens heen) ⇒ knoop wordt als
      root behandeld, geen exception, `level == 0`.
- [ ] Cycle in `parent_pbs_id` ⇒ defensief afgehandeld via
      `visited`-set, geen exception, betreffende knoop als root.
- [ ] `bouwdeel_naam` op de rij komt **altijd** uit
      `PBSItem.bouwdeel_naam` (single source of truth).
- [ ] Lege input (`pbs_results == {}`) ⇒ `build_pbs_rows` levert `[]`.
- [ ] `level` en `sort_path` correct gezet (root: `level == 0`,
      `sort_path == (pbs_id,)`; descendants oplopend).
- [ ] `RunResult` heeft nieuw veld `pbs_rows: list[PBSResultRow]` met
      default `[]`; bestaande contractvelden blijven semantisch gelijk.
- [ ] Happy path in `run_service.run(...)` levert gevulde `pbs_rows`
      met correcte lengte en aggregatie; bestaande `rows`/`metrics`-
      asserties blijven groen.
- [ ] Foutpaden in `run_service.run(...)` (`RUN_PRECONDITION_NOT_MET`,
      `RUN_INTERNAL_ERROR`) leveren `pbs_rows == []`.
- [ ] Bestaande mode-doorgifte (`full_recompute`, `parallel`) blijft
      correct.
- [ ] Geen Qt-imports in `result_view_service` of `run_service`.
- [ ] `python -m pytest` is volledig groen.
