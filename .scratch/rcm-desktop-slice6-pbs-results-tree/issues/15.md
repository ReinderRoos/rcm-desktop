# Issue 15 — `PBSTreeNode` + `build_pbs_tree(rows)`

**Status:** ready-for-human  
**Type:** AFK  
**User stories covered:** US5, US13, US14 (deels), US19, US20, US21 (deels)

## Parent

Bron: `../PRD.md`.

## What to build

Lever de **pure adapterlaag** om uit een bestaande `list[PBSResultRow]` (slice 5)
een **deterministische boom** te maken, **zonder Qt** en **zonder** wijziging aan
`RunResult`, `build_pbs_rows` of de kern.

End-to-end gedrag van deze slice (zonder tree-view / validate-window):

- Nieuwe immutable datatype(s) voor een boomknoop (conceptueel: `pbs_id`,
  referentie naar de bijbehorende `PBSResultRow`, `children` als gesorteerde
  lijst).
- Publieke functie `build_pbs_tree(rows: list[PBSResultRow]) -> list[RootNode]`
  (naam mag equivalent zijn; gedrag staat vast): bouwt alleen hiërarchie en
  sibling-volgorde; **geen** herberekening van totalen — alle numerieke waarden
  blijven die van `PBSResultRow`.
- **Sibling-sort:** binnen één parent alfabetisch op `pbs_id` (los van
  dict-iteratie).
- **Root-sort:** root-knopen alfabetisch op `pbs_id`.
- **Parent/kind-kanten:** uit `parent_pbs_id` op elke rij; kind alleen onder een
  ouder als er een rij met die `pbs_id` als ouder bestaat in de (gededupeerde)
  invoerkaart.
- **Defensief (consistent slice 5):** onbekende `parent_pbs_id` ⇒ knoop wordt
  **root**; cycle ⇒ geen exception, boom blijft consistent (geen nieuwe policy
  tenzij tijdens TDD een gap met slice 5 blijkt — dan documenteren en alignen).
- **Dedupe:** bij meerdere rijen met dezelfde `pbs_id` wint de **eerste in
  invoervolgorde** voor de id→rij-kaart; tweede en volgende worden genegeerd;
  geen crash.
- Lege invoer `[]` ⇒ lege lijst roots.

Type shape (samenvattend, uit PRD):

```
PBSTreeNode:
- pbs_id: str
- row: PBSResultRow
- children: list[PBSTreeNode]  # alfabetisch op pbs_id
```

## Acceptance criteria

- [ ] Pure module uitbreiding naast bestaande PBS-rijbouw: `PBSTreeNode` (of
      gelijkwaardig) en `build_pbs_tree(rows)`; **geen** Qt-imports.
- [ ] `build_pbs_tree([])` levert `[]`.
- [ ] Roots staan alfabetisch op `pbs_id`; children per parent alfabetisch op
      `pbs_id`.
- [ ] Elke knoop draagt de **slice-5-rij** mee; geen herberekening van
      `*_total` of `unavailability_pct_total`.
- [ ] Dubbele `pbs_id` in invoer: alleen **eerste** rij telt in de lookup;
      gedrag is getest en gedocumenteerd in een testnaam/docstring.
- [ ] Onbekende parent ⇒ root; cycle ⇒ geen exception; gedrag sluit aan bij
      verwachting uit slice 5-data (tests met miniatuur-pesten waar nodig).
- [ ] Publieke tests slaan alleen aan op **observable boomstructuur** (welke id
      onder welke parent), niet op interne tussenstructuren.
- [ ] `python -m pytest` volledig groen.
