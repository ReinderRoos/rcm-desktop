## What to build

Eén interne **NB-bucketreeks (per FM)**-spine in de Effectimpact-deepmodule
(`rcm_core/effect_impact_service.py`): één bouwer levert per FM én per
`EffectNbFilterSet` de gepresenteerde NB per horizonbucket. Zowel
`nb_scalar_for_fm` (reductie: levensduur-som / jaargemiddelde / één kalenderjaar)
als `nb_yearly_series` (de reeks zelf) reduceren/presenteren voortaan uit die
spine. Het publieke oppervlak blijft ongewijzigd.

Onderdeel hiervan is de **Bug 1-fix**: de mapping
`ContributionPresentation → EffectPresentation` in
`rcm_desktop/adapter/contribution_chart_service.py` (`_effect_presentation`) mag
`year_choice == "average"` niet meer platslaan naar `horizon="lifecycle"`. De
gemiddelde-jaar-semantiek die `_unavailability_scalar` vandaag heeft, wordt door
de spine gedeeld voor zowel het lege als het gevulde pad. `_fm_contribution_value`
routeert NB voortaan altijd via `nb_scalar_for_fm` (ook bij lege filter);
`contribution_value_for_fm` blijft bestaan voor niet-NB-metrics.
