## What to build

Lever het pure, herbruikbare run-contract op de adapterlaag dat een geladen
`RCMProject` doorrekent via de bestaande kern, plus de daarvoor benodigde
state-spine in `AppState`. Geen Qt-UI, geen runner, geen window-aanpassingen
in deze slice.

End-to-end gedrag van deze slice (zonder UI-aanraking):

- Een nieuwe pure functie/contract `run_service.run(project, project_path,
  *, full_recompute=True, parallel=False) -> RunResult` voert een volledige
  analytische run uit door **één** dunne aanroep op
  `rcm_core.incremental_run.run_incremental_analysis(...)`.
- `RunResult` heeft een vast contract met:
  - `status`: `"done"` of `"error"`
  - `summary`: korte NL-samenvatting (1-2 regels)
  - `metrics` met drie kerncijfers
    - `fm_result_count`: aantal `FMResult`-rijen
    - `total_lifecycle_faalmomenten`: som van `expected_failures` over alle
      `FMResult`s (UI-vocabulaire: **"faalmomenten"**)
    - `total_cost_eur`: som van `total_cost_eur` over alle `FMResult`s
  - `error: UserFacingError | None` met code uit
    `{RUN_PRECONDITION_NOT_MET, RUN_INTERNAL_ERROR}`
- De service mapt foutpaden defensief:
  - geen project ⇒ `RUN_PRECONDITION_NOT_MET`
  - onverwachte exception in de kern ⇒ `RUN_INTERNAL_ERROR`
- `AppState` krijgt twee nieuwe, onafhankelijke velden + signalen:
  - `last_project: RCMProject | None` + `project_changed`
  - `last_run: RunResult | None` + `run_changed`
- Bestaande `last_result`/`result_changed` en `last_preview`/
  `preview_changed` blijven inhoudelijk en gedragsmatig ongewijzigd.
- `validate_runner` wordt minimaal uitgebreid zodat het bij geslaagd laden
  het project op `AppState.last_project` zet (via een tweede signaal of
  via een eenvoudige slot-koppeling); de runner zelf voert verder geen
  run-logica uit. UI-zichtbaar gedrag uit slice 1/2 verandert niet.

## Acceptance criteria

- [x] `rcm_desktop.adapter.run_service.run` is pure adapter-code zonder
      Qt-imports en gebruikt uitsluitend `rcm_core.incremental_run` als
      kernkoppeling, met `full_recompute=True` en `parallel=False` als
      defaults.
- [x] `RunResult` bevat `status`, `summary`, `metrics` en optioneel
      `error`. `metrics` heeft exact de velden `fm_result_count`,
      `total_lifecycle_faalmomenten`, `total_cost_eur`.
- [x] Happy path-test (mock op `run_incremental_analysis`):
      `RunResult.status == "done"`; metrics worden correct uit een
      gestubde `IncrementalRunResult` afgeleid.
- [x] Foutpad-test: project ontbreekt ⇒ `status == "error"` en
      `error.code == "RUN_PRECONDITION_NOT_MET"`.
- [x] Foutpad-test: kern werpt onverwachte exception ⇒
      `status == "error"` en `error.code == "RUN_INTERNAL_ERROR"`.
- [x] Mode-doorgifte-test: bij `full_recompute=True` wordt de juiste
      kwarg aan de kern doorgegeven (assertion op aanroep-args).
- [x] `AppState` heeft `last_project` + `project_changed` en `last_run`
      + `run_changed`; de bestaande `last_result`/`last_preview`-tests
      blijven groen.
- [x] `validate_runner` zet `AppState.last_project` op het geladen
      project bij status `valid`/`valid_with_warnings`; bij
      `invalid`/`error` blijft `last_project` `None` (test toegevoegd).
- [x] Bestaande validate- en preview-tests blijven semantisch gelijk.
- [x] `python -m pytest` is volledig groen.
- [x] Geen Qt-imports in `run_service`; alle nieuwe Qt-tests skippen
      netjes met `pytest.importorskip("PySide6")`.
