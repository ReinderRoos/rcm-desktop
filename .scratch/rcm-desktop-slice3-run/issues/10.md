## What to build

Maak het in issue 09 gebouwde run-contract zichtbaar voor de gebruiker en
bouw de volledige signaalflow van adapter naar UI. Deze slice levert het
end-to-end-gedrag waarmee de analist na een geslaagde validate met één klik
een `run --full` uitvoert en direct de status + drie kerncijfers ziet.

End-to-end gedrag van deze slice:

- Nieuwe `RunRunner` (analoog aan `ValidateRunner`) op een `QThread`:
  - Statussen: `idle`, `busy`, `done`, `error`.
  - Re-entrancy-guard: een tweede `start()` tijdens een lopende run wordt
    afgewezen (`False`).
  - Emit `result_ready` met `RunResult` en `state_changed` voor
    UI-rendering.
  - Geen cancel-pad.
- Validate-window krijgt een **Run-knop naast de Validate-knop** in
  dezelfde knoppenrij bovenaan.
- Run-knop is alleen enabled als:
  - `AppState.last_result.status in {"valid", "valid_with_warnings"}`, en
  - `AppState.last_project is not None`, en
  - `RunRunner` is niet `busy`.
- Tijdens een lopende run is de Run-knop disabled; na afloop weer enabled
  zodra de runner `idle` wordt.
- Onder het preview-paneel verschijnt een `QGroupBox` "Analyseresultaat"
  met:
  - statuslabel (NL via `messages.py`)
  - samenvattingsregel
  - drie value-rijen voor de kerncijfers (`QFormLayout`):
    - `#FM-results`
    - totale **faalmomenten** lifecycle
    - totale kosten in euro
- Reset-discipline (volledig leegmaken + `AppState.last_run = None`):
  - bij wijziging van het pad-input,
  - bij start van een nieuwe validate-run,
  - bij start van een nieuwe analytische run.
- Foutpaden tonen een NL-melding inline (status-label) én via een modaal
  dialog (`ERROR_DIALOG_TITLE`):
  - `RUN_PRECONDITION_NOT_MET`
  - `RUN_INTERNAL_ERROR`
- Alle nieuwe NL-strings staan gecentraliseerd in
  `rcm_desktop/messages.py`. Vocabulaire: **"faalmomenten"** (niet
  "falingen") en **"niet-beschikbaarheid"** (niet "onbeschikbaarheid").

## Acceptance criteria

- [x] `RunRunner` bestaat in `rcm_desktop.adapter` met statussen
      `idle`, `busy`, `done`, `error` en een re-entrancy-guard.
- [x] `RunRunner.start()` retourneert `False` bij een tweede aanroep
      tijdens een lopende run; eerste run gaat door en levert
      `result_ready` met een `RunResult`.
- [x] Bij interne fout in `run_service` (gesimuleerd) ontvangt de UI een
      `RunResult` met `status == "error"` en
      `error.code == "RUN_INTERNAL_ERROR"`.
- [x] Validate-window toont een Run-knop naast de Validate-knop; de knop
      is disabled bij start (geen `last_result`/`last_project`) en
      enabled na simulatie van een geldige validate + project.
- [x] Tijdens `RunRunner.busy` is de Run-knop disabled; na afloop weer
      enabled.
- [x] Validate-window toont een `QGroupBox` "Analyseresultaat" onder het
      preview-paneel met statuslabel, samenvatting en drie kerncijfers
      (`QFormLayout`).
- [x] Bij `run_changed`-signaal met `done`-result staan correcte waarden
      voor `#FM-results`, totale **faalmomenten** lifecycle en totale
      kosten in het paneel.
- [x] Bij start van een nieuwe validate- of run-actie of bij wijziging
      van het pad-input wordt het run-paneel eerst leeg en
      `AppState.last_run` op `None` gezet.
- [x] Bij `RUN_PRECONDITION_NOT_MET` en `RUN_INTERNAL_ERROR` toont de UI
      een begrijpelijke NL-melding inline én via een modaal dialog met
      `ERROR_DIALOG_TITLE`.
- [x] Alle nieuwe NL-strings staan in `rcm_desktop/messages.py`;
      vocabulaire **"faalmomenten"** en **"niet-beschikbaarheid"** wordt
      gehanteerd.
- [x] Geen views importeren rechtstreeks uit `rcm_core` (behalve typing
      waar strikt nodig).
- [x] Qt-tests skippen netjes met `pytest.importorskip("PySide6")` als
      `PySide6` niet beschikbaar is.
- [x] Nieuwe Qt-signaaltest dekt: `RunRunner` emit `state_changed`-flow
      (`busy` → `idle`), levert `result_ready` met `RunResult`, en
      weigert re-entry.
- [x] Nieuwe view-rendertest dekt: Run-knop disabled/enabled-gating,
      paneel-render bij `done`-result, en reset-gedrag bij nieuwe run.
- [x] `python -m pytest` is volledig groen.
