**Triage:** ready-for-agent  
**Type:** AFK

## Parent

## What to build

End-to-end: **Start analyse** op een ongewijzigd gevalideerd project **hergebruikt FM-cache** (~5 s op Haarlem-fixture i.p.v. ~120 s cold). **Herbereken analyse** (knoplabel wanneer cache beschikbaar) dwingt **volledige herberekening**. Motor draait **parallel** waar `run_incremental_analysis` dat ondersteunt.

Implementeer een **Qt-vrije run-beslissingsmodule** met smalle API (`user_intent`, `use_cache`, `parallel`) die `fm_cache_available` en bestaande incrementele run-semantiek hergebruikt. **RunRunner** (en waar trivial **ValidateWindow** runner) roept die module aan — geen gedupliceerde if-logica in views.

## Acceptance criteria

- [ ] On gewijzigd Haarlem-fixture: run via werkruimte-runner met cache-hit roept `run_incremental_analysis` met `full_recompute=False` (test via monkeypatch/spy).
- [ ] Expliciete herbereken: `full_recompute=True` ongeacht cache.
- [ ] Parallel default **true** voor volledige runs; sequential fallback bij `BrokenProcessPool` blijft werken (bestaand kern-gedrag).
- [ ] Knoplabel **Start** vs **Herbereken** blijft gekoppeld aan `fm_cache_available` (bestaand UX-contract).
- [ ] Unit tests op beslissingsmodule + minstens één adapter-test op runner-gedrag.
- [ ] Bestaande `test_incremental_run` en `test_desktop_analysis_cache_service` blijven groen.
