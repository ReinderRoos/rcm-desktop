**Type:** AFK

## Parent

## What to build

Breid `FmEditorDialog` uit met tabblad **Effecten** zodat de analist effecttoekenningen voor **één faalwijze** kan beheren end-to-end (laden → bewerken → OK → incrementele run).

**FM-effectlinks**

- Lijst/beheer van links voor de actieve `fm_id`: `klasse_id`, `fractie`, `aanname_fractie`.
- Toevoegen, wijzigen, verwijderen binnen FM-scope.

**PM-effectlinks**

- Per PM-taak van deze FM (IN, TST, REV, SVO): gekoppelde PM-effectlinks met `fractie` en `aanname_fractie`.

**Effectklassen (bestaand)**

- Inline bewerken van gekoppelde effectklassen (`omschrijving`, `cost_gevolg_eur`, `categorie`, …) via registry `effect_klassen`.
- **Geen** knop “nieuwe effectklasse” in v1.

Validatie en commit via bestaande `FmEditBundleService` / `FmEditCommitService`; geen apart commit-pad.

## Acceptance criteria

- [ ] Tab Effecten zichtbaar en functioneel na issue 02 (geen placeholder meer voor dit tabblad).
- [ ] Wijziging `fractie` op FM-effectlink → OK → opgeslagen in project + incrementele run.
- [ ] PM-effectlink voor een IN/TST/REV/SVO-taak van deze FM kan worden toegevoegd en verwijderd.
- [ ] `cost_gevolg_eur` van gekoppelde effectklasse kan worden gewijzigd en blijft FK-geldig.
- [ ] Poging nieuwe effectklasse aanmaken is niet beschikbaar in UI.
- [ ] Unit of pytest-qt: effectwijziging leidt tot commit en hash-gewijzigde FM in `affected_fm_ids` (minstens de bewerkte FM).
- [ ] Validatiefout (ongeldige FK, fractie buiten bereik) blokkeert OK met NL-feedback.
