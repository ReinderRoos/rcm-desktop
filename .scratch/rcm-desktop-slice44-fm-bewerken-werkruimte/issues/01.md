## What to build

Leg de **ruggengraat** voor faalwijze-bewerken zonder UI: uitbreiding van de **Editing schema registry** en Qt-vrije adapter-deep-modules zodat één FM-scope geladen, gewijzigd, gevalideerd en gecommit kan worden met daarop een **incrementele run**.

**Editing schema registry**

- Nieuwe entiteiten: `fm_effect_links`, `pm_effect_links`, `task_groups` (velden, FK-regels, `field_types` inclusief nested `TimeDuration` waar nodig).
- Uitbreiding `faalwijzes` met bewerkbare velden voor latere tabs (`repair_quality`, `eindgevolg`, `notes`, `aanname_*`, `downtime_per_failure` serialisatie).
- Parity met domain model blijft groen (`test_editing_schemas_parity`).

**FmEditBundleService**

- Bouwt `FmEditBundle` voor één `fm_id`: faalwijze-rij, gekoppeld PBS-rij (voor `bouwjaar`), FM-effectlinks, PM-taken van deze FM, PM-effectlinks, bereikbare taakgroepen, effectklassen uit FK-closure.

**FmEditCommitService**

- `clone_with_project` → apply bundles per entiteit → `validate` → `build_project` → optioneel atomisch save (pad + conflict-check) → `run_incremental_analysis(full_recompute=False)`.
- Retourneert `FmEditCommitResult` (ok, errors, `affected_fm_ids`, `RunResult`).
- Presentatiecache / werkruimte-hydrate via bestaande `RunService`-patronen na succesvolle run.

**CmCostSplitMapper**

- Split/merge `cost_cm_eur` ↔ materiaal + arbeid (adapter-only; geen nieuwe diskvelden).

**FaalwijzenEditService**

- Light consolidatie: geen tweede `EDITABLE_FIELDS`-waarheid; slice-7 grid blijft subset.

Geen `FmEditorDialog` en geen werkruimte-wijzigingen in deze issue.
