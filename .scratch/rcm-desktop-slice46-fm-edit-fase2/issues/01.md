## What to build

**Adapter**

- Bewerkbare velden voor het grid afleiden uit **Editing schema registry** (`ENTITY_SCHEMAS["faalwijzes"]`) via een expliciete grid-allowlist — geen losse hardcoded set die divergeert van de registry.
- `apply_bulk_change(fm_ids, field, raw_value) -> BulkChangeResult` op de faalwijzen-edit façade; zelfde coercion/validatie als `apply_change` (default: all-or-nothing per call).
- `failure_type` en `is_evident` in de allowlist; passende raw→storage mapping (NMF ja/nee ↔ `is_evident`).

**UI (nog in ValidateWindow — geen panel-extract)**

- Twee nieuwe bewerkbare kolommen: faaltype (combo: random/aging), NMF (bool/delegate).
- Contextmenu of toolbar: “pas faaltype/NMF toe op **selectie**” (bulk via service).
- Bestaande run/save/dirty-flow van ValidateWindow ongewijzigd.

**Tests**

- Unit: bulk happy path (N FM’s, één veld); bulk geblokkeerd bij validatiefout (geen partial apply).
- Unit/table model: kolommen tonen registry-waarden voor type + NMF.
