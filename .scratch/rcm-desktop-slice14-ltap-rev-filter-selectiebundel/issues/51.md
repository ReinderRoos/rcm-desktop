# Issue 51 — Bundelactie strikt vanuit zichtbare LTAP-tabelselectie (all-or-nothing)

**Triage:** done  
**Type:** AFK

## Parent

PRD: `.scratch/rcm-desktop-slice14-ltap-rev-filter-selectiebundel/PRD.md` (slice 14).

## What to build

Maak de LTAP-bundelactie strikt selectie-gedreven: alleen op dat moment zichtbare en
geselecteerde detailrijen vormen de bundelinput.

Gedragscontract:

- geen geldige selectie => hard blokkerende foutmelding (geen fallbackpad);
- bevat selectie niet-verschuifbare taken (bijv. SVO/WET) => volledige actie afkeuren
  (all-or-nothing) met duidelijke redenen per relevante PM-id;
- geldige selectie => bundelverschuiving uitsluitend op die selectie toepassen;
- na succesvolle of afgekeurde actie blijft UI-state voorspelbaar binnen actieve
  jaar/filtercontext.

## Acceptance criteria

- [x] Bundelinput komt uitsluitend uit zichtbare geselecteerde LTAP-detailregels.
- [x] Lege/ongeldige selectie geeft een duidelijke blokkerende melding zonder handmatige PM-id fallback.
- [x] Niet-verschuifbare selectie leidt tot all-or-nothing afkeur met redengevende feedback.
- [x] Geldige selectie verschuift alleen geselecteerde taken en laat andere zichtbare taken ongemoeid.
- [x] End-to-end pytest-qt flowtests dekken succespad en beide foutpaden.
