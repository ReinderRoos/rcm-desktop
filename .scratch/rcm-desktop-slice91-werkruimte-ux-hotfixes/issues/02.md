# Issue 02 — Toolbar side-aware: output-chrome verbergen op Input

**Triage:** done

## What to build

Toolbar-zichtbaarheid in de resultatenwerkruimte moet afhangen van **werkruimte-zijde**
en **actieve view**, niet alleen van legacy `modus`.

Achtergrond: input-views in de view-registry hebben `legacy_modus=None`. Bij switch
naar Input blijft `modus` op de vorige output-modus staan (bv. LCC). Daardoor plant
de orchestrator nog steeds output-toolbar (metric-toggle, NB-effectfilter in shared row).

End-to-end gedrag:

- Op **Input-zijde** (`workspace_side == input`): output-toolbar-elementen zijn
  verborgen — shared metric/NB-filter rij, bijdragen-toolbar, LCC-toolbar, FM-output
  toolbar. Geen output-chrome boven entity-grids.
- Op **Output-zijde**: bestaand gedrag per modus/view blijft intact (slice 71/74/85).
- NB-effectfilter wordt **niet** getoond boven `input.faalwijzen` of andere input
  entity-grids.
- Switch Input → Output herstelt de toolbar die bij de sticky output-view hoort.

Implementatie via `ResultsWorkspaceOrchestrator.plan_ui_sync` (toolbar-planners),
niet via ad-hoc `setVisible` in het venster.
