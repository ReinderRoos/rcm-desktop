## What to build

Het NB-effectfilter moet opnieuw opgebouwd worden zodra analytische run-resultaten
beschikbaar zijn — niet alleen bij project-load.

End-to-end gedrag:

- Na project-load zonder run (of met lege `fm_core_results`) blijven klassen zonder
  bijdrage uitgegrijsd (bestaand slice 85-gedrag).
- Zodra `AppState` een voltooide run krijgt (`RunResult.status == "done"` met
  `fm_core_results`), wordt het NB-effectfilter opnieuw opgebouwd via de bestaande
  presentatie-seam (`build_nb_effect_filter_presentation` → `NbEffectFilterCombo`).
  Klassen met bijdrage worden weer selecteerbaar.
- Hetzelfde refresh-pad moet lopen na cache-hydrate bij project-validatie
  (`_after_project_validated` → `set_last_run(hydrated)`), zodat heropenen van een
  project met cache geen permanent grijs filter achterlaat.
- Geen wijziging aan pruning-logica zelf; alleen **wanneer** refresh wordt getriggerd.

## Acceptance criteria
