## What to build

De **tracer bullet** van de Input-zijde: één generiek, schema-gedreven
entiteiten-grid, met **Faalwijzen** als eerste afnemer.

End-to-end:

- Generiek grid in een eigen module (veralgemening van
  `ValidateFaalwijzenPanel`): kolommen, typen en validatie uit
  `ENTITY_SCHEMAS`; per view alleen configuratie (entiteit + kolompreset).
- Bewerken via de bestaande tabulaire editing-pipeline
  (parse/validate/commit); schema-backed en project-backed FK's gedragen
  zich zoals elders; dirty-markering loopt via de normale projectflow.
- Qt-vrije kolompresets: declaratieve lijst default-zichtbare kolommen per
  view, valideerbaar tegen het schema.
- Filterrij (slice 81) geïntegreerd: kolomtypen uit het schema bepalen het
  filtertype.
- De Input-view **Faalwijzen** vervangt de placeholder uit slice 79; het
  Validate-venster blijft bestaan.

TDD: presets-golden + projectie-/configuratietests eerst, dan
pipeline-regressie met entiteit-parametrisatie, dan venster.

## Acceptance criteria

- [ ] Faalwijzen-view opent onder Input met de preset-kolommen.
- [ ] Celwijziging in het grid → zelfde parse/validate/commit-resultaat als
      in `ValidateFaalwijzenPanel` (regressietest).
- [ ] Bewerking markeert het project dirty en loopt in de save/run-flow mee.
- [ ] Filterrij werkt op het grid (deelstring op een tekstkolom).
- [ ] Presets golden-getest; alle presetkolommen bestaan in het schema.
- [ ] `tests/test_editing_schemas_parity.py` blijft groen (schema's gelezen,
      niet gewijzigd).
