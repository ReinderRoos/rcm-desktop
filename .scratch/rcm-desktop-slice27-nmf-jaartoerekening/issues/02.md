## What to build

Maak **niet-merkbaar falen (NMF)** modelleerbaar en **afdwingbaar** vóór de NMF-motor
(issue 03): scenario-filter en validatie, end-to-end van projectinvoer tot geweigerde run.

**Scenario NMF-override (M2b):** uitbreiding `pm_tasks_for_scenario`:

- Naast bestaande CM-regel (SVO ∨ `is_wettelijk_verplicht`) altijd **alle IN- en
  TST-taken** opnemen die aan een faalwijze met `is_evident == false` gekoppeld zijn.
- PM-scenario blijft: alle taken.
- Deze taken volgen het **volledige PM-pad** (kosten, downtime, ontdekking) — geen
  “gratis” test in CM; het is een **modelvoorwaarde**, geen strategische PM-keuze.

**Validator `FM_NMF_REQUIRES_TEST` (DS-3a):**

- Elke niet-evidente faalwijze zonder gekoppelde IN/TST → **fout** in `validate_project`.
- Run-pad (incremental run / desktop run service) **start niet** zolang structuurfouten
  bestaan.
- Verwijder de stille motor-fallback waarbij ontbrekende test leidt tot detectievertraging
  **0** (geen onderinschatting meer).

**Adapter:** `build_project_for_scenario` blijft dunne wrapper; scenario-run-tests dekken
CM-project met NMF-IN/TST.

## Acceptance criteria

- [x] `pm_tasks_for_scenario(..., CM)` bevat alle IN/TST gekoppeld aan niet-evidente FM's,
      ook als ze geen SVO/wettelijk zijn.
- [x] `pm_tasks_for_scenario(..., PM)` bevat nog steeds alle `pm_id`'s.
- [x] Validator levert foutcode/message voor NMF-FM zonder IN/TST; geen waarschuwing-only.
- [x] Run/integration-test: project met NMF zonder test → run geweigerd of geen resultaat
      met successtatus.
- [x] Bestaande demo-/scenario-tests blijven groen na realistische fixture-aanpassing
      (NMF-FM's hebben IN/TST).
- [x] Geen `"WET"`-substring-check teruggebracht; filter blijft data-driven.
- [x] Statische check: motor zet bij ontbrekende test **niet** stil `expected_detection_delay_hr = 0`
      zonder fout (voorbereiding issue 03).
