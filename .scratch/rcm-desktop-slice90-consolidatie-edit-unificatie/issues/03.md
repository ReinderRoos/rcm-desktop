## What to build

**Tracer bullet** voor operationele consolidatie (werkstroom A): bij een
mislukte run, validatie of commit blijft de volledige stack trace beschikbaar
in logs, terwijl de analist nog steeds een nette Nederlandse melding ziet.

End-to-end:

- Adapter-services die breed vangen (`run`, `validate`, `fm-edit-commit`,
  `isograph-open-flow`, `model-settings`, `validate-runner`) loggen de exceptie
  via stdlib `logging` (exception info, geen traceback naar de UI).
- `UserFacingError` draagt de onderliggende oorzaak mee (`__cause__` of
  equivalent) zodat stroomopwaarts kan loggen zonder de gebruikerstekst te
  wijzigen.
- Eén logger-configuratie op applicatieniveau; logbestand naast bestaande
  cache-bestanden (geen volwaardige logging-infrastructuur).
- Bestaande user-facing meldingen en error-codes blijven ongewijzigd.

TDD op de adapterlaag: per aangepast service één test dat een geforceerde
interne fout (a) de bestaande `UserFacingError`-melding oplevert én (b) de
oorzaak in keten/log aanwezig is (prior art: run-service-tests met seam-patch
op `rcm_core.incremental_run as ir`).

## Acceptance criteria

- [ ] Brede `except Exception`-paden in de genoemde adapter-services loggen de
      stack trace (niet zichtbaar voor de analist).
- [ ] `UserFacingError` behoudt de bestaande code en Nederlandse message.
- [ ] De onderliggende exceptie is traceerbaar via cause chain of log-record.
- [ ] Minimaal één regression-test per aangepast foutpad (run + één ander pad).
- [ ] Geen wijziging aan user-visible dialog- of statusbalk-teksten bij normale
      fouten.
