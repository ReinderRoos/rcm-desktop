## What to build

**Inspectorpaneel** in modus **FM-detail** van de resultatenwerkruimte: selectie op de bestaande FM-tabel drijft een read-only detailzone met lifecycle-totalen en traceerbaarheid — nog **zonder** jaartabel/reconcile-UI (issue 04).

End-to-end:

- FM-detail-pagina: **verticale split** (of stacked) — FM-tabel boven, inspector onder; beide tegelijk zichtbaar.
- **Single-row selectie** op FM-tabel; eerste geselecteerde rij → laad view via `fm_verification_service` uit actief scenario-`RunResult` (zelfde bron als FM-tabel).
- Inspector toont: identiteit (`fm_id`, omschrijving, PBS, bouwdeel), **lifecycle-blok** (faalmomenten, downtime-componenten, kosten, effectbijdragen compact), **FM-invoerhash**.
- **Lege staat** zonder selectie (korte NL-tekst, bijv. “selecteer een faalwijze”).
- Inspector **alleen zichtbaar/actief in modus FM-detail**; geen state leak naar Top 10 of Tijdsplot.
- Bij **PBS-scope-wissel**: selectie resetten of valideren zodat geen FM buiten scope wordt getoond.
- Geen Risico-aggregaat als primaire KPI in inspector (consistent met slice 33).
- Labels via `messages`; view praat alleen via adapter (geen `rcm_core`-imports behalve typing-only).
- **pytest-qt smoke:** run + open werkruimte → FM-detail → selecteer rij → inspector toont verwachte `fm_id` en minstens één lifecycle-label; hash zichtbaar indien project geladen.

**Niet in deze slice:** `fm_verification_year_table_model`, jaartabel-widget, reconcile-indicator (issue 04).
