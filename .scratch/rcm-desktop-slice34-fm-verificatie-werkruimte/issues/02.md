## What to build

Nieuwe **Qt-vrije** adapter-deep module `fm_verification_service` die uit `RCMProject` + `FMResult` een frozen `FMVerificationView` bouwt (contract uit PRD).

End-to-end (service + tests, geen UI):

- **Identiteit:** `fm_id`, faalwijze-omschrijving, `pbs_id`, bouwdeel-naam (uit project/FM).
- **Lifecycle-samenvatting:** `expected_failures`, downtime-componenten (raw, detection, PM, totaal), CM/PM/totaal kosten, `effect_bijdragen` als compacte tuple.
- **Jaarrijen:** per kalenderjaar (`modeljaar` + horizonindex, zelfde mapping als LCC/Tijdsplot) bucket-waarden uit `horizon_profile` — faalmomenten via **zelfde proxy-pad** als Top 10/LCC (`contribution_horizon_value_service` / `lcc_profile`-patroon), plus `cor_eur`, `cor_downtime_hr`, `hidden_nb_hr` uit profile.
- **Reconcile:** `sum(year_rows.faalmomenten) ≈ lifecycle.expected_failures` (tolerantie 1e-3); waar profile compleet ook downtime/kosten volgens prior art (`test_desktop_contribution_horizon_value_service`, NB-proxy). Bij ontbrekend `horizon_profile`: `profile_missing=True`, `reconcile_ok=False`, vaste `reconcile_notes` — geen stille OK.
- **FM-invoerhash:** `compute_fm_hash(project, fm_id)`; `None` als FM niet resolveerbaar.
- Publieke entrypoint (bijv. `build_fm_verification_view`) exporteerbaar via adapter `__init__` indien conventie dat vereist.
- Unit-tests: FM met bekend `horizon_profile` → N jaarrijen + reconcile OK; FM zonder profile → missing + notes; lifecycle-velden matchen motor-`FMResult`.

**Niet in deze slice:** Qt-modellen, werkruimte-view, inspector-layout.
