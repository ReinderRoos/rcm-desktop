**Triage:** ready-for-agent  
**Type:** AFK

## Parent

PRD: `.scratch/rcm-desktop-slice86-pbs-volgorde-navigatie/PRD.md` (slice 86).

## What to build

Het fundament in `rcm_core`: een expliciet presentatieveld `volgorde` op het
PBS-item dat wél gepersisteerd maar níet meegerekend wordt.

End-to-end:

- Domain model: nieuw veld `volgorde` (int) op `PBSItem`; mee in
  `to_dict()`/`from_dict()` (`.rcm.json`).
- Migratie: ontbrekend veld bij inlezen → volgorde = huidige
  lees-/importpositie, zodat bestaande projecten identiek renderen.
- **Uitgesloten van globale digest én FM-invoerhash**: alleen `volgorde`
  wijzigen verandert geen van beide vingerafdrukken; een rekenveld wijzigen
  doet dat wel (controle dat de uitsluiting niet te breed is).
- Editing schema registry: `volgorde` als veld op de pbs-entiteit;
  **parity-tests bijwerken** (AGENTS.md: `models.py` + `schemas.py` wijzigen
  → parity moet blijven slagen, anders drift).
- Geen `CACHE_INPUTS_VERSION`-bump (geen JSON-vormwijziging in rekeninput).

## Acceptance criteria

- [ ] Round-trip: `volgorde` overleeft `to_dict()`/`from_dict()`.
- [ ] Vingerafdruk-stabiliteit: alleen `volgorde` wijzigen → digest en
      FM-invoerhash identiek; rekenveld wijzigen → wel anders.
- [ ] Migratietest: project zonder `volgorde` behoudt de leesvolgorde.
- [ ] `tests/test_editing_schemas_parity.py` bijgewerkt en groen.
- [ ] Incrementeel/cache-gedrag getest via de afgesproken seam (patch op
      `rcm_core.incremental_run as ir`).
